# Beautiful Seodang AI Project

이 폴더는 아름다운서당 학생들이 `Codex`, `Claude` 같은 AI 도구를 프로젝트 단위로 활용할 때 기준점으로 쓰는 템플릿이다.

핵심 목적은 세 가지다.

1. 토론, 발표, 회의, 스터디 자료를 한 폴더에 모아 AI가 맥락을 읽게 만든다.
2. AI에게 막연히 묻지 않고, `자료 -> 질문 -> 피드백 -> 수정` 흐름으로 활용한다.
3. 토론과 프로젝트의 과정을 기록해 이후 교수진/운영진이 재활용 가능한 자산으로 남긴다.

## 추천 폴더 구조

- `context/`
  - 프로젝트 개요, 목표, 참여자 정보
- `materials/`
  - 발제문, 읽을 자료, 발표 초안
- `logs/`
  - 회의 메모, 토론 기록, 피드백 로그
- `prompts/`
  - 자주 쓰는 프롬프트
- `outputs/`
  - AI가 정리한 결과물 초안

## Codex / Claude에서 어떻게 쓰면 좋은가

### 1. 폴더 전체를 프로젝트로 연다

- 토론 주제, 발제 초안, 회의 메모, 이전 피드백 로그를 함께 둔다.
- AI가 파일 맥락을 읽을 수 있도록 하나의 프로젝트 폴더에 묶는 것이 중요하다.

### 2. 먼저 `context/project_brief.md`를 읽게 한다

AI는 자료가 많아질수록 중심을 놓치기 쉽다. 그래서 가장 먼저 아래 문서를 읽게 해야 한다.

- 우리 스터디/프로젝트 목적
- 이번 세션 주제
- 청중 수준
- 원하는 산출물
- 금지사항
- AI에게 기대하는 역할
- 과정 중심으로 볼 평가 포인트

### 3. 그 다음 `materials/`와 `logs/`를 읽게 한다

좋은 순서는 다음과 같다.

1. 프로젝트 브리프
2. 이번 주 발제 자료
3. 지난 토론 기록
4. 받은 피드백
5. 현재 수정 중인 초안

### 4. AI에게는 역할을 명확히 준다

예:

- 발표 리뷰어
- 토론 사회자 보조
- 피드백 코치
- 반론 생성자
- 회의록 정리자
- AI Facilitator
- Socratic Tutor

역할을 명시하지 않으면 답이 평평해진다.

## Codex에서 추천하는 요청 방식

```text
이 프로젝트 폴더 안의 `context/project_brief.md`, `materials/week03_draft.md`, `logs/week02_discussion.md`를 읽고,
너는 이번 세션의 피드백 코치 역할을 맡아라.

다음 형식으로 답해라.
1. 핵심 주장 요약
2. 논리적으로 약한 부분
3. 청중이 물을 질문 7개
4. 보완해야 할 슬라이드 포인트
5. 다음 수정 우선순위
```

## Claude에서 추천하는 요청 방식

```text
프로젝트 폴더의 문서를 바탕으로 이번 발표 초안을 리뷰해줘.
특히 다음에 집중해줘.
- 논리 비약
- 청중 이해도
- 반론 가능성
- 표현의 명확성

답변은 발표자 피드백 메모 형식으로 정리해줘.
```

## 대화 로그는 어떻게 넣는가

가장 좋은 방식은 메신저 복붙이 아니라, 정리된 텍스트 파일로 넣는 것이다.

예:

- `logs/week03_raw_notes.md`
- `logs/week03_ai_feedback.md`
- `logs/week03_final_recap.md`
- `logs/week03_process_review.md`

### 추천 형식

```md
# Week 03 Discussion Log

## 발언 요약

- A:
- B:
- C:

## 주요 쟁점

- 쟁점 1
- 쟁점 2

## 미해결 질문

- 질문 1
- 질문 2
```

## AI에게 피드백을 잘 받는 법

### 나쁜 요청

- "이거 어때?"
- "피드백 줘"

### 좋은 요청

- "논리 구조가 약한 부분만 지적해줘"
- "청중이 헷갈릴 표현을 찾아줘"
- "반대 입장에서 공격적으로 질문해줘"
- "사회자라면 어떤 질문 순서로 진행할지 제안해줘"
- "결과보다 과정 기준으로 부족한 점을 짚어줘"
- "우리 팀 토론에서 합의가 약했던 부분을 찾아줘"

## 가장 유용한 4가지 활용

1. 발표 초안 리뷰
2. 토론 질문 설계
3. 회의록 요약
4. 반론 및 보완 포인트 생성

## 아름다운서당에 특히 맞는 활용

### 1. 고전 텍스트 토론

- 핵심 논제 추출
- 현대 이슈 연결 질문 생성
- 반대 해석 생성

### 2. 캡스톤 프로젝트

- 문제 정의 문장 정리
- 팀 토론 로그 분석
- 발표 리허설 질문 생성

### 3. 과정 중심 평가 준비

- 문제 정의 과정 정리
- 팀 토론 흐름 요약
- 해결안이 어떻게 도출되었는지 설명 문장 생성

## 운영 원칙

1. AI는 초안을 만든다.
2. 사람은 판단하고 선택한다.
3. 중요한 주장과 근거는 원문으로 다시 확인한다.
4. 좋은 프롬프트와 결과물은 `prompts/`, `outputs/`에 남겨 팀 자산으로 축적한다.
