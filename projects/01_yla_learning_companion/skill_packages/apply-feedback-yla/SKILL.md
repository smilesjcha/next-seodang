# apply-feedback(yla)

피드백을 받은 직후 학생은 보통 두 가지 함정 중 하나에 빠진다 — (1) 모든 피드백을 다 반영하려다 자료가 너덜해지거나, (2) 어디부터 손댈지 막막해 미루다 잊어버리거나. 이 skill은 그 사이를 잡아준다 — 피드백을 카테고리·위치·우선순위로 항목화해서.

## 핵심 원칙 (왜 이게 중요한가)

1. **고친 본문 생성 금지.** AI가 본문을 만들어주지 않는다. 무엇을 어디에 어떻게 반영할지의 *방향*까지만.
2. **피드백 거절도 학생 권한.** 모든 피드백을 무비판 수용해야 하는 게 아니다. 받아들이지 않을 피드백이 있으면 "이 피드백을 받아들이지 않는 이유" 한 줄을 적도록 권한다 — 자기 사고를 단단히 하는 훈련.
3. **위치 명시.** 항목마다 "어느 자료의 어느 단락/슬라이드"를 명시한다. 위치가 모호하면 학생이 손대지 못한다.

## 입력

- **(필수)** 받은 피드백 (구두로 받은 것을 학생이 메모한 형태도 허용)
- **(필수)** 어느 자료에 반영할지 (보고서 / PPT / 에세이) 명시
- **(선택)** 자료 본문 (가능하면 — 위치 정확히 짚을 수 있음)

## 생성 규칙

### 1) 피드백 카테고리 분류

- **A. 사실/논리 오류** — 즉시 수정 필요 (틀린 사실, 논리 비약)
- **B. 관점 보강** — 새 관점 추가, 깊이 보강
- **C. 표현 다듬기** — 모호·반복·문체
- **D. 구조/형식** — 단락·슬라이드 순서, 길이

피드백 한 덩어리가 두 카테고리에 걸치면 두 항목으로 쪼갠다.

### 2) 항목별 위치·작업·우선순위

각 항목에 대해:
- **위치**: 자료의 어느 부분 (단락 N / 슬라이드 N)
- **작업**: 무엇을 추가/수정/삭제할지 (방향만, 본문 X)
- **우선순위**: 상/중/하
  - **상**: A 카테고리 또는 핵심 주장 직결 항목
  - **중**: B·C 일부, 글의 완성도 좌우
  - **하**: D, 표현 다듬기 수준

### 3) 피드백 거절 칸

받아들이지 않을 피드백에는 별도 칸을 준비. 학생이 "이 피드백은 받아들이지 않는다 — 왜냐하면 ..."를 한 줄 적도록.

거절 사유 예시:
- "이 피드백은 내 핵심 주장을 무너뜨려서, 다른 글에서 다룰 주제로 분리"
- "근거가 약하다는 지적은 동의하나, 이 자리에서는 의도적으로 단순화"

### 4) 학생 응답 처리

"우선순위 상부터 학생이 직접 고치도록 안내. 고친 결과를 보내주면 검토해드립니다"로 종료.

## 출력 형식

```markdown
# 피드백 반영 가이드 — <자료 종류>

## 받아들일 피드백

| 코드 | 카테고리 | 위치 | 작업 (방향만) | 우선순위 |
|---|---|---|---|---|
| [A1] | 사실/논리 오류 | 보고서 본론 2단락 | 인용 출처 페이지 추가 | 상 |
| [B1] | 관점 보강 | 보고서 결론 | 반대 관점 1줄 인정 후 학생 입장 강화 | 중 |
| [C1] | 표현 | 슬라이드 3 bullet 2 | 추상적 표현 → 구체 사례로 | 하 |
| ... | ... | ... | ... | ... |

## 작업 순서
1. **상** 항목부터: [A1]
2. **중**: [B1], [B2]
3. **하**: [C1], [D1]

## 거절 후보 (학생이 결정)
| 피드백 | 거절 이유 (학생이 직접 작성) |
|---|---|
| <피드백 한 줄> | [학생 보완 필요: 왜 받아들이지 않는지] |
| <피드백 한 줄> | [학생 보완 필요: ...] |

> 받아들이지 않을 피드백이 있다면 그 이유를 한 줄로 적어두세요. 자기 사고를 단단히 하는 훈련입니다.

---
**다음 단계.** 우선순위 상부터 학생이 직접 고친 후 보내주시면 검토해드립니다. 본문은 학생이 직접 채워야 합니다.
```

## 가드레일 (자가 점검)

- [ ] AI가 고친 본문을 만들어주지 않았는가? (방향까지만)
- [ ] 모든 피드백을 무비판 수용 강요하지 않았는가? (거절 칸을 마련했는가)
- [ ] 거절 이유는 학생이 직접 채우도록 빈칸으로 남겼는가? (`[학생 보완 필요]`)
- [ ] 항목별 위치(단락·슬라이드)를 명시했는가?
- [ ] 우선순위 상/중/하를 매겼는가?

## 연결되는 다른 skill

자료 단위 내부 피드백(에세이 한 편)은 `revise-essay(yla)`. 슬라이드 한 장만 다듬는다면 `update-ppt(yla)`. 캠프·작품집용 최종본 점검은 `finalize-portfolio(yla)`.
