# check-ai-cautions(yla)

YLA의 학습 원칙은 [`docs/yla/06_ai_cautions.md`](../../../../docs/yla/06_ai_cautions.md)에 있다 — 핵심은 "AI는 학생 사고를 *대신* 만들지 않고, 학생이 읽고 토론한 내용을 *발표 가능한 구조*로 바꿔주는 보조 도구"라는 것. 이 skill은 그 원칙이 학생 자료에서 무너지지 않았는지 학생 본인이 자가 점검하도록 돕는다.

## 핵심 원칙 (왜 이게 중요한가)

1. **점검이 또 다른 의존이 되면 안 된다.** "이게 답이다"가 아니라 "다시 생각해 보라"의 톤. 학생이 "이 자료 OK"라는 도장을 받으러 오는 게 아니라, 자기 자료를 거리 두고 보는 연습.
2. **비난 금지.** 🔴이 떴다고 학생을 비난하지 않는다. **회복 경로**(어느 skill을 써서 어느 부분을 다시 만들면 되는지)를 함께 제시한다.
3. **학생 자가 점검이 본질.** AI가 점검하는 게 아니라, AI가 학생이 점검할 수 있게 돕는다. 따라서 출력은 "이 부분이 의심스럽다, 학생이 다시 봐달라"의 형태.

## 입력

- **(필수)** 점검할 자료 본문 (보고서·에세이·PPT·발표 스크립트)
- **(선택)** 학생이 AI를 어떻게 사용했는지 한 줄 회고 (예: "구조만 잡고 본문은 직접 썼다")

## 점검 항목 (06_ai_cautions의 5개 함정)

### 1) 보고서 대필 의심
- 신호: 학생 평소 어조와 다른 매끄러운 문장이 다수
- 신호: 비슷한 문장 구조가 단락마다 반복 (AI 특유의 리듬)
- 신호: 학생 노트·메모와 본문의 어휘·관점이 갑자기 점프

### 2) 정답 결론 의심
- 신호: "결론적으로 ~이다"의 단호한 결론
- 신호: 학생 사고 흔적(고민·전환·자기 의심) 없음
- 신호: 양면성·예외 없이 한 방향으로만 흐름

### 3) 토론 의견 대신 작성
- 신호: 토론 메모가 너무 정돈되어 실제 발언 흔적 없음
- 신호: 발언자 이름이 없거나 모두 같은 톤으로 정리됨
- 신호: 토론 시간 대비 메모 양이 너무 많거나 너무 매끄러움

### 4) 학생 고유 관점 삭제
- 신호: 발표자 본인의 관점(항목 8)이 일반론으로 대체
- 신호: 1인칭("나는", "저는") 거의 없음
- 신호: 학생 자신의 경험·상황이 자료에서 사라짐

### 5) 요약만 의존
- 신호: 인용·반응이 없고 책 요약된 내용만
- 신호: 페이지 표시가 없는 인용·"~이라고 한다" 식 출처 모호
- 신호: 책에 대한 평가만 있고 책에서 학생이 *느낀 것*이 없음

## 가드레일 (자가 점검)

- [ ] "이게 답이다"가 아니라 "다시 생각해 보라" 톤을 유지했는가?
- [ ] 🔴 항목이 있을 때 학생을 비난하지 않았는가? (회복 경로를 함께 제시했는가)
- [ ] 각 신호에 자료의 *구체적 위치*를 짚었는가? (모호한 지적 X)
- [ ] 학생이 의도적으로 그렇게 쓴 부분일 수도 있음을 열어두었는가? ("학생이 결정할 사항" 칸)

## 연결되는 다른 skill

🔴 항목별 회복 경로 (예시):
- 보고서 대필 → `outline-essay(yla)` (구조만 다시) + 본문은 직접
- 정답 결론 → `prep-debate(yla)` (반론 보고 결론을 단단하게)
- 토론 의견 대신 → `summarize-debate(yla)` (메모 원본부터 다시)
- 학생 고유 관점 삭제 → 항목 8(발표자 관점)을 한 줄 직접 다시 쓰기
- 요약만 의존 → `record-reading(yla)` (인용·반응 노트부터 다시)
