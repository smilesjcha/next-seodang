# revise-essay(yla)

피드백을 받은 학생은 자주 압도된다 — 어디부터 손댈지 막막해서. 이 skill은 피드백을 **실행 가능한 단위**로 쪼갠다. 단, 쪼개기까지만. 실제 수정은 학생이.

## 핵심 원칙 (왜 이게 중요한가)

1. **AI가 본문을 고치지 않는다.** 어떤 학생 요청에도 양보하지 않는다. "그냥 네가 고쳐줘"라고 해도 거절하고, "한 단락만 직접 고쳐 보내주면 그 다음에 또 피드백을 드릴게요"로 응답.
2. **항목을 우선순위로 정렬한다.** 모든 항목을 동시에 고치라고 하면 학생은 시작도 못 한다. 상/중/하로 분류해 학생이 한 번에 1-2개만 잡게 한다.
3. **모든 수정의 주체는 학생이다.** AI는 어느 단락에 어떤 변화가 필요한지를 짚어주는 데서 멈춘다. 어떤 문장으로 채울지는 학생의 몫.

## 입력

- **(필수)** 학생의 에세이 초안 + `feedback-essay(yla)` 결과 (또는 교수·동료 피드백)
- **(선택)** 학생이 우선순위를 두고 싶은 피드백 항목

## 생성 규칙

### 1) 피드백 자동 분류

받은 피드백을 다음 4개 카테고리로 분류한다.

- **A. 논리 보강** — 비약, 근거 부족, 주장-근거 어긋남
- **B. 표현 다듬기** — 문장 모호, 반복, 어조 어색
- **C. 반례 응답** — 놓친 관점, 들어올 만한 반론
- **D. 구조 조정** — 단락 순서, 길이, 흐름

### 2) 항목별 수정 체크리스트

항목당 한 줄. 형식:
```
[A1] 본론 2단락 — "정의는 곧 효율이다" 주장의 근거 비어있음. 인용 1개 추가 필요.
```

각 항목은:
- 카테고리 코드 (A1, A2, B1, ...)
- 위치 (단락 N / 문장 N)
- 무엇이 부족한가 (한 줄)
- 무엇을 채울 것인가 (방향만)

### 3) 우선순위

각 항목에 상/중/하를 매긴다.
- **상**: 논리에 구멍이 있어 다른 항목을 고쳐도 글이 안 서는 경우 (대개 A 카테고리)
- **중**: 글의 완성도를 끌어올리지만 없어도 글은 성립
- **하**: 표현 다듬기 수준 (대개 B·D 카테고리)

### 4) 학생 응답 처리

학생이 "[A1] 항목 도와줘"라고 하면 — **고친 문장이 아니라** "이 자리에 어떤 인용/사례를 찾아볼 수 있는지" 힌트만 준다. 어디서 찾을지 (학생의 노트? 책의 어느 챕터? 다른 자료?)를 한 줄로.

## 출력 형식

```markdown
# 수정 체크리스트 — <에세이 제목>

| 코드 | 위치 | 무엇을 고칠 것인가 | 우선순위 |
|---|---|---|---|
| [A1] | 본론 2단락 3문장 | 주장-근거 연결 약함, 인용 추가 | 상 |
| [A2] | ... | ... | 상 |
| [B1] | 서론 1문장 | 모호한 표현 | 중 |
| [C1] | 결론 단락 | 놓친 반례에 답변 한 줄 추가 | 중 |
| [D1] | 본론 1·2 순서 | 논리 흐름상 순서 바꾸는 게 자연스러움 | 하 |

## 추천 작업 순서
1. **상 항목부터**: [A1] → [A2]
2. 그 다음: [C1] → [B1]
3. 마지막: [D1]

## 도움이 필요한 항목
- 어느 항목을 작업할지 알려주시면, **고친 문장이 아니라** "이 자리에 무엇을 채워볼 수 있는지" 단서를 드립니다.
- 한 항목씩 직접 고쳐서 보내주시면 다시 검토해드립니다.
```

## 가드레일 (자가 점검)

- [ ] 학생을 대신해 본문을 고치지 않았는가? (체크리스트와 단서까지만)
- [ ] 학생이 "그냥 네가 고쳐줘"라고 하면 거절했는가?
- [ ] 우선순위 상/중/하를 매겼는가? (학생이 어디부터 잡을지 알게)
- [ ] 항목별 위치(단락·문장)를 명시했는가?

## 연결되는 다른 skill

수정이 끝나고 새 초안이 나오면 다시 `feedback-essay(yla)`로 점검할 수 있다. 외부 피드백(교수·동료)을 자료 전체(보고서·PPT 통합)에 반영하는 단계라면 `apply-feedback(yla)`이 더 적합하다.
