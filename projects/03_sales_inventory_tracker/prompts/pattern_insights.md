# pattern_insights(si)

## 목적
`04_decompose_patterns.ipynb`와 `05_macro_context.ipynb` 결과를 받아, 매입 의사결정에 쓸 **비즈니스 인사이트**로 옮긴다. 통계 결과를 단순 나열하지 않는다.

## 사용법

```
pattern_insights(si) — 다음 분해 결과를 비즈니스 언어로 해석해줘.

대상:
- product_id: <SKU>
- 분석 기간: <YYYY-MM ~ YYYY-MM>

STL 분해 요약 (pattern_summary_*.md):
<notebook 04 출력 markdown 그대로 붙여넣기>

매크로 컨텍스트 요약 (macro_context_*.md):
<notebook 05 출력 markdown — 회귀 R², 계수, 시나리오 표>

(선택) STL/anomaly 차트 첨부
(선택) 회사 상황: 공급사 다변화 정도, 발주 주기, 결제 통화
```

## Claude가 할 일

1. 다음 4개 축으로 한국어 narrative (각 2-3문장):
   - **추세** — 장기 가격 방향. 누적 변화율의 의미를 비즈니스 용어로.
   - **계절성** — 매입 적기·고비용기를 카운트다운식으로 (예: "9월부터 10주 안에 N월 매입 결정 필요").
   - **이상치** — 발견된 가격 충격이 일회성인지 구조 변화의 시그널인지 가설.
   - **매크로 영향** — R²이 의미하는 "매크로 의존도". 환율·유가·원가 중 가장 큰 계수의 비즈니스 함의.
2. **이 데이터로 답할 수 없는 것** 한 단락 — 모델이 모르는 차원(신규 공급사 협상력, 시장 점유율 변동, 정책 변화 등).
3. 추천 다음 액션 1-3개 — 어떤 노트북·프롬프트(`procurement_strategy(si)`, `derivatives_insight(si)`)로 넘어갈지.

## 출력 형식
markdown. 의사결정자(MD/팀장)가 그대로 회의 자료에 옮겨도 되는 톤.

## 가드레일
- 통계 용어를 그대로 쓰지 않는다 ("R²=0.31"가 아니라 "매크로가 변동의 약 1/3을 설명").
- 입력에 없는 사실을 만들지 않는다 — 노트북 결과로 검증되지 않는 추측 금지.
- "이게 답이다"는 단정 금지. 모든 결론은 "이런 구조로 보인다, 다음 검증은 ..."의 톤.
- 회사 정보를 외부에 노출하지 말라는 한 줄 알림 (작성자가 채팅에 붙여넣은 회사명·SKU 코드는 외부에 공유 금지).
