# 왜 Claude인가 — 3가지 이유

**1. 길게 읽는다**
보고서 한 권, 논문 여러 편, 프로젝트 폴더를 한 번에 붙여서 **맥락을 잃지 않고** 읽힌다

**2. 사고를 안 빼앗는다**
\"대신 써줘\"보다 \"구조를 점검해줘\"에 더 잘 맞는다 — 우리가 만든 가드레일을 안정적으로 지킨다

**3. 한 두뇌가 여러 자리에 들어간다**
채팅, 코딩, 팀 협업, 디자인 — 4개의 진입점이 **같은 컨텍스트 자산 위에서** 일관되게 작동

> 오늘 중요한 건 \"Claude가 최고냐\"보다, **맥락을 축적하고 재사용하는 방식**이다.

# 같은 AI, 다른 화면 경험

**Chat-only** (ChatGPT 웹, Gemini 웹) — 텍스트 입력 → 텍스트 출력. 결과를 사용자가 다른 도구로 옮긴다. 즉, 사람이 끝까지 **중간 관리자**로 남는다.

**Agentic** (Claude Code, OpenAI Codex Desktop) — 폴더 위에서 직접 작업하고, 사람은 \"복붙 담당\"이 아니라 **검토자·의사결정자**로 이동한다:

- **계획 모드** — 변경 전 의도를 보여주고 사용자 승인 받음
- **편집 수락** — 파일별 diff를 미리보기 + 부분 거부 가능
- **권한 요청** — 위험한 명령은 사용자에게 사전 확인
- **Prototype Preview** — 만드는 중인 UI를 화면에서 즉시 미리보기
- **Wireframe Preview** — 디자인 와이어프레임을 화면에서 바로 보면서 수정

> 같은 AI 두뇌. 화면이 받아들이는 방식이 다를 뿐.

# YLA 5단계 학습 = AI가 들어가는 5개 자리

| 단계 | 학생 활동 | AI의 자리 |
|---|---|---|
| 읽기 | 고전 정독 | 시대 배경·핵심 개념 설명 |
| 쓰기 | 보고서 직접 | 구조 점검·논리 피드백 |
| 말하기 | 발표 PPT | **사전 체크리스트** 후 초안 |
| 토론 | 조별 합의 | 반론·예상 질문 생성 |
| 수정 | 피드백 반영 | 항목 분해·우선순위 매기기 |

> AI는 학생의 사고를 **대신**하지 않고, **다음 단계**로 넘기는 도구.
> 즉 AI는 정답 기계가 아니라, YLA 학습을 밀어주는 **보조 operating system**.

# AS-IS / TO-BE — YLA 학생 시점

| 영역 | AS-IS (지금) | TO-BE (Claude 활용 후) |
|---|---|---|
| **발표 준비** | 발표 전날 밤샘 PPT 만들기 | 평일 보고서 작성 → 토요일 30분이면 PPT 초안 |
| **AI 사용** | \"이 책 요약해줘\" — 인용·출처 못 댐 | 배경 설명만 받고 본인이 직접 인용 정리 |
| **글쓰기** | AI에 본문 부탁 → 본인 사고 사라짐 | AI가 거절 → 구조만 받고 본인이 본문 |
| **수업 후 수정** | 피드백이 흩어진 채 1주 흐름 | apply-feedback으로 항목화 → 작품집 반영 |

> 도구가 바뀌는 게 아니다. **시간 분배와 사고 흔적**이 바뀐다.
> 밤샘을 없애는 게 목적이 아니라, **생각할 시간을 앞당기는 것**이 목적이다.

# 5단계 중, 왜 \"말하기\"만 실습 메인인가?

| 단계 | 스킬 | 강의 안 실습 | 강의 밖 자리 |
|---|---|---|---|
| 읽기 | explain-classic, record-reading | △ 1분 시연 | 평일 독서 시간 |
| 쓰기 | outline-essay, feedback-essay, revise-essay | △ 1분 시연 | 평일 보고서 작성 |
| **말하기** | **create-ppt, update-ppt, rehearse** | **● 20분 메인** | **토요일 발표 직전** |
| 토론 | prep-debate, summarize-debate | × 조별 토론 자리 | 수업 중 토론 시간 |
| 수정 | apply-feedback, finalize-portfolio | × 수업 후 | 피드백 받은 뒤 1주 |

**\"말하기\"를 실습 메인으로 고른 4가지 이유:**
- **시각적 즉시성** — PPT 결과는 1초 만에 화면에 뜸 (\"오, 진짜 됐네\" 경험)
- **가드레일 시연 자리** — \"보고서 없으면 거절\"이 강의 메시지의 핵심을 보여줌
- **단일 input · 풍부 output** — 보고서 1개로 슬라이드 + 스크립트 + 시사점까지
- **학생이 가장 \'아쉬운\' 단계** — 평일에 못 끝낸 일을 토요일 아침 30분에 해결

> 나머지 4단계는 강의 후 **본인 학습 흐름에 자연스럽게 들어간다** — 핸드아웃 미션으로 1주 안에 1회 적용.

# Use case 1 : 토요일 발표 준비 — input → output

- **상황**: 다음 토요일 『논어』 3분 개인 발표
- **넣는 데이터**: 본인 보고서/에세이 .md + 발표 형식(3분/5분) + 핵심 주장 1문장 + 발표자 본인의 관점

- **20분 안에 도달**: 본인 발표 자료 1세트 + 자가 수정 회고 한 줄
- **학생이 끝까지 맡는 일**: 인용 선택, 주장 결정, 마지막 문장 고치기

# 학생 사고를 보호하는 두 장치

| **가격 인상 진단** | \"가격이 올랐다\" — 한 마디로 끝 | STL 4패널로 추세·계절성·잔차·매크로 분리 |
| **매크로 영향** | \"환율 때문이겠지\" — 직감 | OLS 회귀로 매크로 설명력 R² 정량화 |
| **매입 시점** | 매월 정해진 날 발주 | z-score·Bollinger·모멘텀 시그널로 적기 식별 |
| **헷지 결정** | \"우리는 너무 작아서 못 한다\" — 회피 | 변동성·매입금액 신호등으로 의미 판정 |

> 회사를 바꾸는 게 아니다. **회사를 보는 눈**이 바뀐다.
> 한 문장짜리 감각을, 설명 가능한 의사결정 재료로 바꾸는 과정이다.

# 가격 상승의 4가지 원인

| 원인 | 합리적 행동 |
|---|---|
| **추세** (지속적) | 장기 계약·연간 단가 협상 |
| **계절성** (반복) | 비수기 미리 매입 |
| **잔차 충격** (일회성) | 일시 대기 후 평균 회귀 |
| **매크로** (FX·유가) | 헷징, 결제 통화 변경 |

> STL 4패널 한 화면이 이 4개를 분리해 보여준다.
> 같은 \"인상\"이라도 원인이 다르면, 행동은 완전히 달라진다.
