# 세미나 준비 회의 메모 예시

## 회의 정보

- 주제: AI Native 시대의 직무 구조와 Multiplier 역량
- 목적: 넥스트서당 발표 준비
- 참석자: 발표자, 운영 담당, 기록 담당, 피드백 담당

## 메모 원문

- 오늘 발표는 단순히 AI 툴 소개로 끝나면 안 되고, 학생들이 자기 삶과 커리어에 연결해 생각할 수 있어야 한다.
- 특히 아름다운서당 맥락에서는 AI를 사고 대체가 아니라 사고 확장 도구로 소개해야 한다.
- 첫 파트에서는 AI Native라는 말이 왜 중요한지, 그리고 단순 사용자와 무엇이 다른지 분명히 정리할 필요가 있다.
- 중간 파트에서는 실제 요청자 3명의 사례를 보여주면서 연구, 사업, 구매 영역에서 어떤 종류의 Agent가 현실적으로 유용한지를 구체적으로 보여주자.
- 박정윤 사례에서는 논문에서 근거 문장을 찾는 문제를 통해 RAG나 retrieval 관점을 직관적으로 설명할 수 있다.
- 전재현 사례에서는 자동화 대상이 아직 명확하지 않은 상태를 보여주고, 업무를 분해해서 AI 적용 포인트를 찾는 사고 과정을 보여주면 좋겠다.
- 이돈현 사례에서는 숫자를 맞히는 예측보다, 가정과 시나리오를 비교하는 의사결정 보조가 더 중요하다는 메시지를 강조하자.
- 학생들이 이해하기 쉽게 제품 맵도 필요하다. ChatGPT, Claude, Perplexity, Colab, Codex 정도만 소개하고 너무 많은 툴은 넣지 말자.
- Agent 파트에서는 Prompt, Workflow, Agent 차이를 꼭 구분해서 설명해야 한다.
- Functions는 반드시 코드로 보여주고, MCP는 개념 정도까지만 설명하자.
- A2A는 역할 분업 관점에서 짧게 소개하면 충분하다.
- Colab 실습은 너무 어려우면 안 되고, 회의 메모 정리, 토론 질문 생성, 발표 피드백 정도가 적절하다.
- 실습 코드는 코딩을 잘 모르는 사람도 이해할 수 있게 주석을 매우 자세히 달아야 한다.
- 발표 후반부에는 AI Native 운영법을 넣고, 좋은 프롬프트를 쌓고 로그를 남기고 검수 루프를 만드는 것이 왜 중요한지 설명하자.
- 프로젝트 폴더 구조도 보여주자. context, materials, logs, prompts, outputs 정도면 충분하다.
- Q&A에서는 아마 비개발자도 Agent를 만들 수 있는지, 어떤 툴부터 시작해야 하는지, AI를 쓰면 사고력이 약해지지 않는지 같은 질문이 나올 가능성이 높다.
- 오늘 안으로 슬라이드 초안의 핵심 메시지와 실습 노트북을 맞춰야 한다.
- 발표 자료에 들어갈 예시 질문도 몇 개 준비해야 한다.
- 다음 주 전까지 리허설 일정을 잡아야 한다.
- 실습 노트북은 OpenAI API Key를 안전하게 주입하는 방법으로 정리해야 하고, 데모 후에는 키를 회전하는 것이 좋다.

## 결정사항

- 3명의 사례를 강의 전반부 중심 축으로 둔다.
- Agent는 큰 개념보다 작은 함수 호출 루프로 보여준다.
- 실습은 반드시 시연 가능한 수준으로 단순화하되, 결과 품질은 충분히 좋아야 한다.

## 남은 작업

- 슬라이드 문구 다듬기
- Colab 실습 최종 점검
- 발표 피드백 질문 세트 준비
- 리허설 일정 확정

## Trace 기대 포인트

이 문서는 Langfuse Trace에서 아래 흐름으로 보이는 것이 이상적이다.

1. 메인 요청: 회의 메모를 정리해달라는 사용자 요청
2. 함수 호출 1: `summarize_notes`
3. 함수 호출 2: `extract_action_items`
4. 최종 응답: 요약 + 액션아이템 + 발표용 핵심 메시지

즉, 이 예시는 `문서 요약 도구`와 `액션아이템 도구`가 함께 호출되는 사례로 쓰기 좋다.
