# 강의용 Agent 개념 정리

## Agent를 가장 직관적으로 설명하는 법

강의에서는 아래처럼 설명하는 것이 가장 직관적이다.

- `Prompt`: 한 번 묻고 한 번 답받는 구조
- `Workflow`: 사람이 순서를 정해 둔 자동화
- `Agent`: 목표를 주면 상황을 보고 다음 행동을 고르고 도구를 호출하는 구조

즉, Agent는 "조금 더 자율적으로 다음 행동을 정하는 실행 주체"라고 설명하면 된다.

## Agent의 최소 구성

1. 목표
2. 현재 상태
3. 사용할 수 있는 도구
4. 결과를 판단하는 기준
5. 필요하면 반복하는 루프

## 비유

- ChatGPT에게 "이 메일 써줘"는 비서에게 문장 하나 부탁하는 것
- Agent에게 "이 회의 준비 끝내줘"는 비서에게 자료 찾기, 정리, 초안 작성, 빠진 점 확인까지 맡기는 것

## Function Calling

### 어떻게 설명할까

- 모델이 직접 계산하거나 외부 정보를 알 수 없을 때, 미리 정의된 함수를 부른다.
- 즉, "말만 하는 AI"가 아니라 "도구를 쓸 수 있는 AI"가 된다.

### 학생에게 보여줄 예시

- `summarize_notes(text)`
- `extract_action_items(text)`
- `make_discussion_questions(topic)`

## MCP

### 어떻게 설명할까

- MCP는 Agent가 외부 도구, 데이터, 파일 시스템, 서비스와 더 표준적으로 연결되는 방식이다.
- 강의에서는 "USB-C 같은 연결 규격"이라고 비유하면 이해가 빠르다.

### 어디까지 보여줄까

- 개념 설명
- 왜 필요한지
- 어떤 도구와 연결될 수 있는지
- 실제 서비스 수준으로 가면 강력하지만, 오늘은 아이디어 수준까지만

## Agent to Agent

### 어떻게 설명할까

- 하나의 Agent가 모든 일을 다 하지 않고, 역할별 Agent가 협업하는 구조
- 예: `Research Agent`, `Writer Agent`, `Reviewer Agent`

### 학생 수준에서 보여주기 좋은 범위

- 개념도
- 2-agent 협업 예시
- "분업"의 효용 설명

### 과하게 복잡하게 만들지 말아야 하는 이유

- 강의 데모가 multi-agent orchestration으로 가면 핵심이 흐려진다.
- 학생에게는 "작은 Agent 하나를 잘 쓰는 것"이 먼저다.

## 오늘 강의에서 추천하는 메시지

1. `Function Calling`은 오늘 직접 눈으로 보여준다.
2. `MCP`는 연결 표준의 방향성을 소개한다.
3. `A2A`는 역할 분업의 미래이자 확장 개념으로 설명한다.

## 한 문장 정리

> Agent는 AI에게 생각만 맡기는 것이 아니라,
> 도구를 통해 실제 행동까지 맡기는 구조다.
