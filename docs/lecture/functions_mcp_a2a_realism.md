# Functions, MCP, A2A를 강의에서 어디까지 보여줄 것인가

## 결론 먼저

오늘 강의에서는 아래 정도가 가장 적절하다.

1. `Functions`
   - 반드시 보여준다.
   - 가장 직관적이고, 학생도 "아 이렇게 행동이 연결되는구나"를 이해할 수 있다.
2. `MCP`
   - 개념 중심으로 소개한다.
   - "도구 연결 표준"이라는 감각만 주면 충분하다.
3. `A2A`
   - 확장 개념으로 설명한다.
   - 실제 데모는 굳이 복잡하게 만들지 않는다.

## 1. Functions

### 왜 강의에서 좋나

- 자연어 요청이 실제 함수 실행으로 이어지는 모습을 보여주기 쉽다.
- Agent를 "말하는 AI"에서 "행동하는 AI"로 전환해서 이해시키기 좋다.

### 추천 데모

- 공지문 작성
- 회의록 액션아이템 추출
- 토론 질문 생성

## 2. MCP

### 강의 메시지

- MCP는 Agent가 외부 서비스, 파일, 데이터와 연결되는 표준화된 인터페이스다.
- 학생에게는 "여러 도구를 연결하는 통일된 포트" 정도로 설명하면 충분하다.

### 왜 개념 소개에 그칠까

- 실제 MCP 서버 구성과 연결은 강의 시간 대비 복잡도가 높다.
- 오늘 목적은 개발 프레임워크 교육이 아니라, AI Native 사고방식 전달이다.

## 3. Agent to Agent

### 강의 메시지

- Agent마다 역할을 나누면 더 구조적으로 일할 수 있다.
- 예: Research Agent, Writer Agent, Reviewer Agent

### 실제로 어디까지 유용한가

- 복잡한 리서치/문서화/검수 파이프라인에서는 충분히 유용하다.
- 하지만 초심자에게는 단일 Agent부터 익히는 편이 훨씬 낫다.

### 추천 설명 수준

- 개념도 1장
- 역할 분담 예시 1장
- 실제 데모는 생략하거나 매우 짧게

## 학생에게 남겨야 할 현실 감각

- 당장 가장 실용적인 것은 `단일 Agent + 함수 호출`
- 그 다음이 `외부 도구 연결`
- 마지막이 `다중 Agent 분업`

즉, 순서는 다음이 맞다.

1. Prompt를 잘 쓴다.
2. 함수를 붙여서 행동하게 만든다.
3. 파일/서비스와 연결한다.
4. 필요할 때 역할 분업을 만든다.
