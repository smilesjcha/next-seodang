## Part 1. Opening: 왜 이 강의인가

### 1. 제목

- 제목: `AI Native 시대, Agent와 함께 일하는 법`
- 부제: `아름다운서당과 넥스트서당을 위한 실전 가이드`

### 2. 오늘 강의의 핵심 질문

- 질문: `AI를 도구로 쓰는 수준을 넘어, 어떻게 사고와 실행의 파트너로 둘 것인가`

### 3. 오늘의 전체 흐름

- 3명의 실제 요청 사례
- 제품/활용 방식 요약
- Agent 기초
- 실습
- AI Native 운영법

### 4. 오늘 먼저 보여줄 결론

- AI는 답변기보다 `중간 단계 위임기`로 더 유용하다.
- Agent는 사람을 대체하는 개념이 아니라 `판단 전후의 반복 단계를 맡기는 구조`다.

### 5. 아름다운서당 관점의 전제

- AI는 사고 대체가 아니라 사고 확장 도구
- 결과보다 과정
- 툴보다 사고력

### 6. 왜 이 순서로 강의하는가

- 기술 설명부터 하면 추상적이다.
- 그래서 먼저 `누구의 어떤 문제를 어떻게 도울 수 있는가`부터 간다.

## Part 2. 3명의 요청자: 누구를 어떻게 도울 것인가

### 7. 설문 3명 요약

- 연구
- 사업
- 구매

### 8. 3명에게 공통으로 보인 패턴

- AI는 알고 있지만 업무에 넣는 법은 불명확
- 생성보다 정리/탐색/비교/자동화 가치가 큼
- 완전 자율형보다 Copilot + Workflow가 적합

### 9. Case 1 소개: 박정윤

- 연구
- 논문 근거 찾기
- 메일/엑셀 반복 업무

### 10. 박정윤의 진짜 문제

- 근거 문장을 빨리 찾기 어렵다
- 연구 외 반복 사무가 시간을 잡아먹는다

### 11. 박정윤에게 줄 수 있는 Agent 도움 1

- `논문 근거 탐색 Agent`
- 질문 -> 관련 논문/문단 -> 근거 문장 -> 인용 후보

### 12. 박정윤에게 줄 수 있는 Agent 도움 2

- `메일/행정 Assistant`
- 상황/상대/목적/톤 입력 -> 초안 생성

### 13. 박정윤에게 줄 수 있는 Agent 도움 3

- `엑셀 보조 Workflow`
- 표 정리, 컬럼 정규화, 요약표 생성

### 14. 박정윤 사례의 강의 포인트

- 연구자는 생성보다 `검증 가능성`이 중요
- RAG를 가장 직관적으로 설명할 수 있는 사례

### 15. Case 2 소개: 전재현

- 사업
- 반복적인 수동 업무 자동화
- 문제 정의가 아직 덜 선명함

### 16. 전재현의 진짜 문제

- 무슨 일을 자동화할지부터 같이 찾아야 한다
- 업무 로그와 커뮤니케이션이 자잘하게 쌓인다

### 17. 전재현에게 줄 수 있는 Agent 도움 1

- `업무 발굴 Agent`
- 일주일치 업무 -> 반복 업무 후보 -> 우선순위

### 18. 전재현에게 줄 수 있는 Agent 도움 2

- `영업/운영 메시지 Assistant`
- 반복 안내문, 고객 응대, 거래처 메시지

### 19. 전재현에게 줄 수 있는 Agent 도움 3

- `업무 로그 정리 Agent`
- 메일/메신저/노션 -> TODO / Follow-up / 이슈

### 20. 전재현 사례의 강의 포인트

- AI 도입의 시작은 툴 선택이 아니라 `반복 단위 정의`
- 사업 직군은 모델보다 workflow 분해가 먼저

### 21. Case 3 소개: 이돈현

- 구매
- 매출 실적 정리, 수요 예측, 매출 추정

### 22. 이돈현의 진짜 문제

- 데이터 대조와 양식 정리가 크다
- 수요 예측과 협상 근거가 필요하다
- 매출 추정을 계속 수정해야 한다

### 23. 이돈현에게 줄 수 있는 Agent 도움 1

- `실적 정리 Agent`
- 주문 데이터와 거래처 자료 대조

### 24. 이돈현에게 줄 수 있는 Agent 도움 2

- `수요 예측 Copilot`
- 과거 데이터 + 시즌성 + 신규 변수 비교

### 25. 이돈현에게 줄 수 있는 Agent 도움 3

- `매출 추정 시뮬레이션 Assistant`
- 변수 변경 시 시나리오 비교

### 26. 이돈현 사례의 강의 포인트

- AI는 숫자를 대신 믿게 하는 기계가 아니라
- 가정과 시나리오를 빠르게 비교하게 하는 도구

### 27. 세 사례를 한 장으로 묶기

- 연구: 근거 탐색
- 사업: 반복 업무 발굴
- 구매: 시나리오 비교

### 28. 이 3명에게 공통으로 줄 수 있는 메시지

- AI는 정답 생성기가 아니라 `중간 단계 위임기`
- 제일 먼저 해야 할 일:
  - 입력 정의
  - 원하는 출력물 정의
  - 검증 기준 정의

## Part 3. 어떤 제품으로, 어떤 방식으로 도울 것인가

### 29. 제품을 설명하기 전에

- 제품 이름보다 `용도 구분`이 먼저다
- 생각, 탐색, 자동화, 코드, 기록으로 나눠야 한다

### 30. 기본 제품 맵

- ChatGPT
- Claude
- Gemini
- Perplexity
- Colab
- Codex / Claude Code

### 31. 학생/직장인용 가장 쉬운 조합

- ChatGPT or Claude: 사고 정리
- Perplexity: 탐색
- Notion / Docs: 기록

### 32. 발표/토론 준비용 조합

- Claude: 긴 문서 요약
- ChatGPT: 질문 생성
- Codex 또는 Claude Project: 파일 맥락 기반 피드백

### 33. 연구/실무 자동화용 조합

- Colab: 코드 실험
- Codex / Claude Code: 작은 도구 제작
- Sheets/CSV: 반복 업무 자동화

### 34. 언제 어떤 제품을 쓰나

- 답변이 필요할 때
- 비교가 필요할 때
- 초안이 필요할 때
- 파일을 읽고 맥락 이해가 필요할 때
- 작은 실행 도구를 만들 때

### 35. 제품을 잘못 쓰는 방식

- 툴만 바꾸고 workflow는 그대로
- 묻기만 하고 축적은 안 함
- 검증 기준 없이 결과를 소비

### 36. 제품을 잘 쓰는 방식

- 자료를 프로젝트 폴더에 모은다
- 역할을 명시한다
- 요청 형식을 고정한다
- 결과를 다시 자산화한다

### 37. 아름다운서당 학생에게 가장 현실적인 방식

- AI를 `튜터`, `코치`, `사회자 보조`, `피드백 코치`, `논점 정리자`로 쓰기

### 38. 여기서 Agent가 등장하는 이유

- 단순 질문응답을 넘어서
- 자료 읽기, 정리, 질문, 비교, 기록까지 이어지기 시작하면
- Agent 개념이 필요해진다

## Part 4. Agent란 무엇인가

### 39. Prompt와 Agent의 차이

- Prompt: 한 번 묻고 한 번 답
- Workflow: 사람이 순서 지정
- Agent: 목표를 받고 다음 행동을 일부 선택

### 40. Agent를 가장 직관적으로 설명하면

- `도구를 쓸 수 있는 디지털 인턴`

### 41. Agent의 최소 구성

- 목표
- 상태
- 도구
- 판단 기준
- 루프

### 42. 왜 Agent가 필요한가

- 일은 보통 한 번의 답으로 끝나지 않는다
- 읽고, 찾고, 정리하고, 다시 질문해야 한다

### 43. 강의용 예시 1

- 논문 근거 탐색 Agent

### 44. 강의용 예시 2

- 토론 사회자 보조 Agent

### 45. 강의용 예시 3

- 회의록 정리 Agent

### 46. Agent의 한계

- 검증 없는 자율성은 위험하다
- 그래서 오늘은 `작은 Agent`부터 본다

## Part 5. Functions, MCP, A2A

### 47. Function Calling이란

- 모델이 직접 할 수 없는 행동을 함수로 호출

### 48. Function Calling 예시

- 공지문 작성
- 토론 질문 생성
- 회의록 액션아이템 추출

### 49. MCP란

- Agent가 외부 도구와 연결되는 표준 인터페이스

### 50. MCP를 직관적으로 설명하면

- 여러 도구를 꽂는 `USB-C 포트`

### 51. Agent to Agent란

- 역할별 Agent가 협업하는 구조

### 52. 오늘 어디까지 보여줄 것인가

- Functions: 직접 시연
- MCP: 개념 소개
- A2A: 역할 분업 예시

## Part 7. AI Native 운영법

### 58. AI Native가 된다는 것

- 툴을 많이 쓰는 사람이 아니라
- 문제를 구조화하고 축적하는 사람

### 59. 개인/팀 운영 방식

- 프로젝트 폴더
- 프롬프트 자산
- 로그 축적
- 결과물 아카이빙

### 60. Closing

- 한 줄 메시지:
  - `AI Native는 AI를 많이 쓰는 사람이 아니라, AI를 붙여 자신의 사고와 실행을 multiplier로 만드는 사람이다`
