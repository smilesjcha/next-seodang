# 강의 운영 런북

## 시작 전 체크

1. 인터넷 연결 확인
2. Colab 탭 미리 열기
3. 코드 예제 2개 실행 확인
4. PPT에서 데모로 넘어가는 위치 체크
5. 데모 실패 시 대체 스크린샷 또는 코드 출력 준비

## 오프닝 멘트 방향

- "오늘은 AI를 잘 설명하는 강의보다, AI를 어떻게 내 삶의 operating system으로 넣을지 이야기하겠다."
- "중요한 것은 모델 이름이 아니라, 내가 반복하는 문제를 구조화하는 능력이다."

## 현장 흐름

### 1. 관심 끌기

- 모두가 이미 AI를 써봤지만, 왜 생산성 차이는 크게 나는지 질문

### 2. 구조 제시

- AI User
- AI Power User
- AI Native

이 세 단계로 청중을 끌고 간다.

### 3. 사례 연결

- 설문 3명 케이스를 보여주면서 "내 이야기"처럼 느끼게 만든다.

### 4. Agent 파트

- 추상 정의보다 "도구를 쓰는 디지털 인턴"으로 설명

### 5. 코드 데모

- 5~7분
- 핵심은 완성도보다 원리 전달

### 6. 마무리

- 7일, 30일 플랜 제시
- 개인 축적 시스템으로 연결

## 90분 기준 권장 런오브쇼

### 0~10분

- 오프닝
- 아름다운서당 관점의 교육 철학
- 오늘 강의의 전체 구조

### 10~30분

- 설문 3명 사례
- 각 사례별 Agent/Copilot 제안

### 30~40분

- 제품 맵
- 어떤 제품을 어떤 용도로 쓸지 요약

### 40~55분

- Agent 기초
- Prompt, Workflow, Agent 차이
- Functions / MCP / A2A

### 55~65분

- 프로젝트 폴더 기반 AI 협업 방식
- Codex / Claude 활용 예시

### 65~80분

- Colab 실습
- 최소 Agent 코드 시연

### 80~90분

- AI Native 운영법
- Skill Setting
- 아웃풋 퀄리티를 높이는 검수 루프

## Q&A 권장 운영

- 10분 버전:
  - 핵심 질문 3개만 받고 종료
- 20~30분 버전:
  - 도구 선택
  - 진로/직무 질문
  - 실제 업무 적용 질문
  - Agent 실습 확장 질문

## 데모 실패 시 대체 설명

1. 함수 하나만 수동으로 호출해도 충분하다.
2. Agent의 본질은 `입력 -> 판단 -> 도구 -> 결과`라는 점을 다시 잡는다.
3. 학생이 이해해야 할 것은 SDK 문법이 아니라 구조다.

## 질의응답 예상 질문

### "비개발자도 Agent를 만들 수 있나요?"

- 네, 작은 자동화부터 가능하다.
- 다만 복잡한 시스템화는 코드 이해가 있으면 훨씬 강해진다.

### "Agent가 사람을 대체하나요?"

- 단기적으로는 전체 대체보다, 중간 단계 위임과 속도 향상이 핵심이다.

### "뭘 먼저 배우면 되나요?"

- 프롬프트보다 업무 구조화
- 그 다음 함수 호출/자동화 감각
- 마지막으로 도구 연결
